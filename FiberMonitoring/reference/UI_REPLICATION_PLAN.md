# 首页参考图复刻方案

基准：`reference/image.png`（2444 × 1377）。现状：`reference/image copy.png`（3200 × 1904）。

本轮范围：对照截图、阅读代码、给出方案与改动位置；不修改界面或三维实现。

## 1. 复刻目标与边界

- 参考图是唯一视觉基准：保留它的模块位置、宽高比例、字体层级、卡片造型、图标风格、颜色和场景构图。
- 先在与参考图相同的画布尺寸上验证；1920 × 1080 按比例适配，再验证 1600 × 900、1280 × 720。不能直接比较两张不同尺寸、不同宽高比的整屏截图。
- 明确区分操作系统物理像素、浏览器 CSS 像素和 devicePixelRatio，截图记录三者。
- 二维界面以像素对齐为目标。交互三维以相机投影、构图、几何和材质匹配为目标；一张二维参考图不能提供完整的三维资产和被遮挡部分。
- 若最终要求中心画面也逐像素一致，需要固定视角的原图展示或离线渲染；若保留旋转、剖切与实时选中，则必须制作匹配参考的三维资产，并单独验收默认视角。

## 2. 问题与优先级

| 级别 | 发现 | 修复方向 |
| --- | --- | --- |
| 必修 P0 | 资源树“工程场景”折成两行；事件卡片在窄侧栏内挤压、内容裁切 | 为名称、状态、时间分配明确的布局区域；根据内容确定最小高度；移出次级工程里程信息 |
| 必修 P0 | 三维标签彼此重叠，遮挡光纤和监测点 | 按分组固定默认视角标签区域，增加碰撞检测、优先级与边缘约束 |
| 主要 P1 | 场景右侧大块灰白空白，道路纵向穿屏，地下层次不突出 | 先修复默认相机构图，再调模型细节；让道路横向展开、地下剖面成为下半部主体 |
| 主要 P1 | 植被只剩细树干和零散小叶片 | 修复树冠替换逻辑，采用真实乔木树冠，而不是把灌木集合当作树冠 |
| 主要 P1 | 建筑是高频棋盘格方块，抢占前景 | 更换立面和结构细节，控制层高与窗格尺度；退到背景形成天际线 |
| 主要 P1 | 土层、管道像独立放置的模型，缺少剖切整体感 | 连续土层断面、管周土体/垫层、管壁厚度与接头、合理水面和接触阴影 |
| 主要 P1 | 顶部、两侧和底部的比例与参考不一致 | 统一基准画布上的栅格与设计变量，重写冲突的响应式覆盖 |
| 主要 P1 | 波形近乎水平，柱状图集中在一个时间段，风险长期偏红 | 修复采样；设计稳定的参考演示数据；真实数据保持真实统计 |
| 提升 P2 | 导航、卡片图标、发光边缘与参考仍有差距 | 核心构图完成后再还原斜切导航、图标体积感、渐变和局部高光 |

## 3. 二维布局：具体改哪里

### 3.1 整屏骨架

文件：

- `frontend/src/views/DashboardView.vue`
- `frontend/src/assets/styles/dashboard/foundation.css`
- `frontend/src/assets/styles/dashboard/panels.css`
- `frontend/src/assets/styles/dashboard/responsive.css`

参考图测量的初始比例（为手工估读值，实施时应按像素标定）：

- 中间工作区：左侧约 17%、中心约 67%、右侧约 14%，其余为间隔和边距。
- 左侧上方资源面板约占工作区高度 38%，下方事件面板约占 60%，中间保留间隔。
- 右侧图层面板与状态面板高度相近，顶部和底部与中心视口对齐。
- 底部监测区约占整屏高度 18%，避免图表被底部裁切。

当前 `panels.css` 基础列宽为 `274px / 1fr / 242px`；1600px 以下还会变为 `230px / 1fr / 205px`，1300px 以下为 `205px / 1fr / 185px`。两侧变窄后，长中文名称、徽标和时间没有同步调整布局，是局部拥挤的重要原因。

实施：建立侧栏宽度、行高、内边距、字号、边框和发光强度变量；按参考标定后统一引用。不要通过不断加覆盖选择器来堆叠新样式。

### 3.2 左侧资源树

文件：`components/dashboard/ResourcePanel.vue`，`assets/styles/dashboard/panels.css` 的 `.tree-root`、`.resource-tree`，及 `responsive.css`。

当前“工程场景”是 flex 容器里的匿名文字节点，和展开箭头、图标、工程里程抢空间。

实施：

1. 给名称单独包裹元素，并设定可伸缩列。
2. 箭头、图标固定尺寸；“工程场景”保持单行。
3. 工程里程放到单独一行次级说明，或移到详情区域。
4. 默认资源树与参考保持四个主项目，具体光纤子列表通过展开查看。
5. 主视图默认不因次级元数据出现常驻滚动条；展开后允许正常滚动。

### 3.3 实时事件卡片

文件：`components/dashboard/LiveEventPanel.vue`，`panels.css` 的 `.event-cards`、`.event-card-title`、`.event-chainage`，及响应式样式。

实施：

- 明确划分图标、标题、级别、时间和描述区域，避免所有内容在一行互相挤压。
- 标题列使用 `minmax(0, 1fr)`；级别和时间不参与压缩。
- 卡片不沿纵向被 flex 压扁，根据内容规定最小高度和行高。
- 默认完整显示三张卡片和“查看更多事件”。较小窗口允许列表滚动，底部链接保持可见。
- 展示高、中、低三类演示事件时使用独立演示数据，不改变真实事件的等级来匹配颜色。

### 3.4 顶部与底部

文件：

- `components/dashboard/PlatformHeader.vue`、`assets/styles/dashboard/header.css`
- `components/dashboard/OverviewStrip.vue`、`assets/styles/dashboard/overview.css`
- `components/dashboard/TelemetryDock.vue`、`assets/styles/dashboard/telemetry.css`

实施：

- 标题与导航按参考重新分配宽度，标题成为最强文字层级；斜切导航、高光边缘和激活态统一。
- 顶部六张指标卡采用一致的图标位置、标题基线、数字基线、单位和状态灯位置。
- 当前图标主要是线框，参考有更强体积和高光。按原图制作匹配的矢量或栅格图标资产，避免仅靠放大线框图标冒充同等效果。
- 底部四张指标与三张图表共用一个对齐网格，标题、坐标轴、数字和图例适当放大。
- `telemetry-content` 及图表容器必须可收缩，SVG 具有明确可用高度，避免 `height:100%` 与标题、边距相加后溢出。

## 4. 三维：先重构构图，再改资产

### 4.1 默认镜头

文件：`three/hero/HeroCameraController.ts`、`three/core/SceneManager.ts`、`components/dashboard/SceneViewport.vue`。

当前 overview 预设为 `position: [-57, 36, 74]`，`target: [0, -2, 3]`。现状截图也可能包含用户旋转后的视角，不能仅凭截图断言该角度就是默认预设。

实施：

1. 固定默认展示机位，道路长边接近水平，保留参考中的透视方向。
2. 参考图上部展示城市、绿化与车辆，下部展示土层、光纤与管道，两部分视觉面积接近。
3. 以道路边缘、管道两端、监测点、地层标签为投影锚点校准镜头，而不是反复凭感觉改坐标。
4. 根据中心视口长宽比与主体包围盒调整取景；限制只针对环境背景，不裁掉管道与土层主体。
5. 默认机位与俯视、地下、横断面、纵断面独立配置；重置视角可可靠回到参考构图。

### 4.2 植被的明确实现问题

文件：`three/engineering/SceneRealism.ts` 的 `replaceCanopies()`；`three/engineering/CityBuilder.ts` 的 `createTree()`。

代码先删除所有 `simpleCanopy`，再把整个 `shrub.gltf` 集合缩放成宽约 3.7m 的“树冠”。该 glTF 包含四个横向排列的灌木节点，原始高度约 0.25～0.40m；缩放按整个集合的宽度计算，因此每株仍然很小，不能形成参考中的乔木树冠。

实施：更换匹配的行道树资产，按单株的树高、冠幅和树干连接位置归一化。加载成功且边界尺寸校验通过后，再替换备用树冠。灌木素材用于绿化带，不承担乔木树冠。

### 4.3 建筑、天空和灯光

文件：

- `three/engineering/CityBuilder.ts` 的 `createBuilding()`
- `three/engineering/SurfaceTextures.ts`
- `three/hero/HeroEnvironment.ts`
- `three/engineering/SceneLighting.ts`
- `three/core/SceneManager.ts` 的 `setDaylightEnvironment()`
- `three/engineering/SceneRealism.ts`

实施：

- 建筑补立面分格、裙楼、顶部结构和材质差异，减少高频随机窗格，避免近景巨型棋盘纹理。
- 建筑退后并控制高度分布，中心主角是道路剖面而不是办公楼。
- 分离环境反射贴图和可见天空。当前 HDR 同时作为背景与反射来源；应按参考配置蓝天、云层、地平线和统一太阳方向。
- 灯光、曝光、粗糙度统一标定，减少灰白背景和过强漫反射造成的“塑料感”。
- 按性能预算加入接触阴影/环境遮蔽；先检查现有阴影更新策略，再决定实现方式，不默认增加昂贵的全屏后期效果。

### 4.4 土层、光纤与排污管道

文件：

- `three/engineering/GeologyBuilder.ts`
- `three/engineering/RockBedBuilder.ts`
- `three/hero/HeroSewer.ts`
- `three/engineering/SewerBuilder.ts`
- `three/hero/HeroFibers.ts`
- `three/hero/HeroSceneBuilder.ts`

实施：

- 土层形成连续剖切体：上缘承接道路，下缘承接垫层，管道与土体具有明确的埋设关系。
- 参考图每层土的纹理、粒度、颜色各不相同；当前所有层共用同一种 soil 写实纹理，仅靠颜色区分，应改成按层配置。
- 石块形成有厚度的垫层，不像散落的独立颗粒。
- 管道还原金属壁厚、端口、接头、法兰、固定件、观察区域和水流，按参考调整显示尺度。
- 光纤视觉配色与参考的红/蓝/绿对齐时，同时修改三维、图例与资源列表，保持一致。
- 参考的里程、总长、监测点数与现有工程数据不同。严格演示复刻使用独立数据集；真实工程坐标、长度和设备数仍取实际数据，不能为匹配截图而悄悄改工程含义。

### 4.5 标签

文件：`three/engineering/SceneAnnotations.ts`、`three/core/MonitoringSceneSync.ts`、`three/hero/HeroFibers.ts`、`assets/styles/dashboard/scene.css`。

当前标签只是把三维坐标投影到屏幕后加固定偏移，没有标签矩形之间的碰撞检测。

实施：默认视角将土层名排列在左侧、光纤名排列在右侧、告警靠近事件锚点、管道名放在下方；根据标签实际尺寸检测碰撞，保留最小间距并约束在视口内。旋转后仍通过优先级和引导线保持可读。事件数量限制并不能替代标签避让。

## 5. 底部图表为什么“空”

文件：`components/dashboard/MonitoringChart.vue`、`composables/useTelemetry.ts`、`services/mock/MockMonitoringDataSource.ts`。

当前波形为 1000Hz 采样率、10 秒时长、5Hz 正弦波加噪声，共 10000 点。图表每隔 100 点取一个点，也就是每 0.1 秒取一次；5Hz 波形每 0.1 秒恰好经过一次零点，主信号因此被抽没，画出来主要剩噪声。数学核验中，抽样后的无噪声主信号最大绝对值约为 4.4e-12。

实施：

1. 原始波形采用按像素分桶的 min/max 等保峰值采样策略，明确采样点、时间范围和振幅坐标轴。
2. 若匹配参考的平滑趋势图，应展示有明确时间窗口的振幅/RMS 趋势，并配真实时间刻度，而不是把原始波形任意平滑成装饰曲线。
3. 24 小时柱图需要完整时间分布。当前只按最近事件缓存的小时统计，初始化事件集中在当前时段，所以不能自然产生参考图中的全天分布。
4. 参考演示数据提供固定的 24 小时统计与风险区段，保证截图可复现；实时模式保持正常更新和数据语义。
5. 线图当前纵坐标用 `56 - value / maximum * 36`，而刻度按 0～maximum 绘制，轴与曲线并不一致，需要一并修正。

## 6. 执行顺序与验收

1. **参考标定**：固定画布、DPI、字体、机位、时间与演示数据。建立区域边界和关键锚点。
2. **布局纠错**：修复文字换行/重叠、卡片裁切、侧栏比例和底部图表边界。
3. **构图与标签**：实现默认参考机位，确保地下剖面可见，标签互不遮挡。
4. **三维资产**：树木 → 建筑与天空 → 土层与管道 → 车辆和监测硬件；每类逐项比较。
5. **视觉精修**：字体、图标、斜切造型、渐变、细边、高光和局部发光。
6. **验证**：同尺寸截图叠加与差异检查；检查桌面和浏览器两种运行方式；运行类型检查、场景回归和桌面桥接检查。

完成标准：

- 基准画布上的模块边界、间隔、文字基线逐项与参考对齐，不以“感觉差不多”代替截图对照。
- 默认首页完整显示三张事件卡、两侧面板及底部图表；无文字重叠、关键文字断行和非预期裁切。
- 中心画面有完整的城市—道路—土层—光纤—管道层级，没有抢占主体的大块灰白区域。
- 默认视角的土层、光纤、事件和管道标签无碰撞；切换视角、缩放和重置仍然可用。
- 演示模式截图可复现；真实数据模式的统计、设备状态和工程单位不被视觉复刻改写。
- 1920 × 1080、1600 × 900、1280 × 720 适配后可读；记录哪些紧凑布局偏离了基准图，而不是声称所有屏幕都逐像素一致。
- 不以关闭必要三维交互换取表面相似；固定图展示若被选择，应作为明确的展示模式单独标注。

## 7. 所需素材

完整动态三维复刻需要：匹配参考的行道树、玻璃建筑、轿车/货车/公交车、监测箱与支架、金属管道，以及分层土体和天空的素材。现有 asphalt/soil/HDR/灌木只覆盖其中一部分。

素材可由项目建模或使用许可明确的资产。所有模型统一尺度、坐标轴、纹理分辨率和细节等级后再接入；避免通过堆叠模型数量提升“饱满度”。
