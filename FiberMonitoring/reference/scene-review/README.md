## 工程数据约定

原始工程仍为 910 米，首页聚焦 K0+300～K0+400 的 100 米区段。只调整展示坐标：纵向 0.8 倍、地下深度 1.8 倍、管道径向 1.35 倍。光纤、设备与事件使用同一变换，管道和光纤模型的长度元数据仍以原始米为单位。车辆单独作展示放大。界面中的实际里程、设备数、光纤总长、事件等级继续来自现有数据，不照抄参考图中的示例数值。

横断面和纵断面按钮仍为预设观察机位，并非新增可移动的工程切割平面。场景中的树木、车辆和建筑也没有新增物理仿真或车辆实时行驶逻辑。

## 验证结果

- `npm run build:check`、`npm run test:scene`、`npm run test:charts` 通过。
- 桌面窗口桥接烟测、本地 HTTP 服务两项单元测试通过。
- 2444 × 1377、1920 × 1080、1600 × 900、1280 × 720、1600 × 952：标注无碰撞、无越界。
- 五种视角、六项图层、透明度、旋转、重置、水流暂停/恢复、路由离开释放与重新创建、素材故障回退均通过。
- 测试期间无页面脚本异常、无 Three.js 警告、无对外部素材服务器的 HTTP 请求。
- 18 个来源素材的 MD5 与减面树木 GLB 的 SHA-256 校验通过。许可与来源在 `frontend/public/assets/realism/ATTRIBUTION.md`。
- 默认 1920 × 1080 视角约 271 万个提交三角形、713 次绘制调用。双面透明材质改为单次绘制、建筑立面构件合并后，比优化前约 499 万个三角形和 1010 次绘制调用减少。这里是渲染提交量，并非帧率保证；尚未测量锁屏恢复后的实际 Qt 稳定帧率。
- 生产构建仍有 Three.js 所在首页分包大于 500 kB 的 Vite 提示；构建成功。

机器可读结果：`scene-report.json`、`production-report.json`。

## 距参考图仍有的差距

1. 轿车、卡车和公交仍为代码构建的几何模型，外形曲面、灯组、玻璃和轮胎细节不及参考图中的写实车辆。还需匹配角度与车型的高质量资产。
2. 土体已有分层材质和起伏，但仍以连续实体几何为基础，尚缺参考图中的大块岩土断裂、堆积与细碎接触阴影。
3. 路面有物理材质和环境高光，尚无参考图中那样的局部潮湿反射、车辆反射及细腻地表细节。
4. 城市建筑与树冠仍显规则，灯光没有达到离线渲染的接触阴影、复杂间接光和电影级质感；本轮未接入昂贵的全屏反射/环境遮蔽后处理。
5. 仅凭二维参考图无法恢复原始模型与相机；当前是按参考重建的实时场景，尚不能声称像素级一致。
